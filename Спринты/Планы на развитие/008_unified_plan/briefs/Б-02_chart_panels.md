8. **Дефект «сжатие свечи при открытии канала»** (найден на тестовом стенде 2026-10-26, A-01).
   - Что происходит. Поток публикует первые кадры до дозагрузки головы периода, с `bar_complete=false, bar_pending=true`.

     сжимается до одной минуты и восстанавливается. Так же устроены 15m, 1h и 4h.
   - Что нужно. Кадр `bar_pending` того же периода не затирает более полную свечу. Поправленные бары после обрыва связи
     (S8R-FIX-022) должны по-прежнему доходить до графика.
   - Кадры для фикстур — `s8r-evidence/008/A-01/ui/live-frames-{W,M}.json` в репозитории документации.

## Контракт дилерского потока (общий с A-03)

- **История:** `GET /api/v1/market-data/candles/dealer?ticker&timeframe&from&to` — есть с A-01 (1m–4h; D/W/M — 422,
  без T-Invest — 409). Параметр `adjust` (`splits|none`, по умолчанию `splits`) добавляет этот блок.
- **Подписка:** `POST /api/v1/market-data/candles/subscribe?ticker=…&timeframe=…&source=dealer` → `{"channel":
  "dealer:{ticker}:{tf}"}`, ТФ 1m–4h. Второй подписки к T-Invest нет. Делает A-03.
- **WebSocket:** `{"action":"subscribe","channel":"dealer:SBER:5m"}`; события — как у основного канала:
  `{channel, event:"candle.update", data:{timestamp, open, high, low, close, volume, stream_gen, bar_complete,
  bar_pending}}`. Делает A-03.
- Если A-03 ещё не в `develop`, когда этот блок готов, — живое обновление дилерских свечей пишется по контракту и
  проверяется тестами с подставным каналом. Живая проверка — на стенде, когда оба блока в `develop`, в выходные.
  Если контракт придётся менять — сначала вопрос мне.

## Что уже известно из сверки с кодом (2026-10-26, ветка A-01 `2b7c97a`)

- `stores/marketDataStore.ts`: один набор `currentTicker/currentTimeframe/candles`. Кэш `candlesCache` по ключу
  `${ticker}:${tf}`; предел 2 000 свечей — только у копии в localStorage, в памяти — `MAX_CANDLES = 10_000`. Общие для
  всех графиков `crosshairData`, `loading`, `dataSource`. `upsertLiveCandle` отбрасывает свечи не текущего ТФ: второй
  график с другим ТФ живых свечей не получит. Store используют `ChartPage`, `CandlestickChart`, `OpenPositionsLayer`,
  `TimeframeSelector`, `StatusFooter`, `useChartLiveData`, `authStore` и 15 тестов.
- `CandlestickChart.tsx` сам читает `currentTicker/currentTimeframe` из store и вызывает общий `fetchOlderCandles`.
  `OpenPositionsLayer` берёт живую цену из общего `candles`. `TimeframeSelector` — только из store.
- WebSocket: `useWebSocket` держит `Map<channel, Set<callback>>`, повторной подписки на канал нет. На сервере держатели
  канала — множество, повторный `POST /candles/subscribe` при живом стриме возвращает тот же канал.
- `lightweight-charts` 5.2.1, API v5: `chart.addSeries(CandlestickSeries)`. Режим шкалы `mode` не используется.
  Последовательный режим — для 1m–4h: `time` — номер бара, настоящее время — `customValues.barTime`.
- Рисунки: `chartDrawingsStore` — один контекст `{userId, ticker, timeframe, items}`, ключ localStorage
  `drawings:{userId}:{ticker}:{tf}`, на сервере индекс `user_id, ticker, timeframe` (`backend/app/common/models.py`). С
  S8R-FIX-102 рисунки привязаны ко времени свечи. Старые точки без настоящего времени (год < 2000) рисуются по номеру
  бара: при подмешивании дилерских свечей они могут сместиться. До Б-04 это допустимо, в отчёте назвать.
- `user_favorites` (`kind ∈ {instrument, timeframe}`, строка до 50 символов) для раскладки не подходит. Нужно своё
  хранение с JSON настроек.
- Маршрут `/candles` — `mode=viewer|backtest|trading`, `adjust=splits|none` (по умолчанию `splits`). В базе свечи «как
  было», пересчёт при чтении. Фронтенд не передаёт ни `mode`, ни `adjust`. `/candles/dealer` фронтенд не вызывает.

#### G1. Несколько графиков на экране

*Этап:* параллельная дорожка, первым (одна модель панелей); живая свеча D/W/M — дефект, этап 1 · *Статус:* ✅ делаем (принято 2026-10-22); живая свеча D/W/M — ✅ как дефект

**Факты.**

  до 2 000 свечей; контекст рисунков один; WebSocket один с картой каналов `market:{ticker}:{tf}`.
- Moex бэкенд: стрим по ключу (тикер, ТФ) с держателями; 1m и собираемые ТФ подписаны на 1m, 5m — на «родной» 5m:

  приняты в записи D3).

**Решение.**
- **Раскладки на старте:** 1, 2 рядом, 2 друг под другом, 4 (2×2); больше — позже по желанию.

- **Без дублей:** один запрос свечей и один канал на ключ «тикер:ТФ», в T-Invest — одна подписка 1m на тикер (решение 3);

- **Дефект в общий список:** живая последняя свеча D/W/M — свеча дня из REST (у T-Invest «незакрытая»), дальше
  обновление из потока 1m.

**Где в коде Moex.**

  `TimeframeSelector`, `OpenPositionsLayer`, `StatusFooter` — от активной панели.

- Рисунок в правой верхней панели сохраняется для её тикера и ТФ.
- После перезагрузки и на другом устройстве раскладка та же.
