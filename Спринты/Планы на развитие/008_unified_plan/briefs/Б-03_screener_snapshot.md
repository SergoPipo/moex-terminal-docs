## Что сделать

Реализовать в коде часть 1 пункта E1 и пункты E2, E3 (без пометки на графике — она уже сделана в A-05), E4 и правило
A9 в части оборота. Тексты пунктов приведены ниже дословно — они и есть требования. Где написано «по развилке N» —
делать по ответу заказчика из раздела «Развилки».

Порядок: справочник вселенной → история дня по ISS → снимок рынка → скринер → карта → поправки секторов.

1. **Справочник вселенной** (E2, E4, A8) — ежедневная синхронизация:
   - основа — список биржи: акции режима TQBR из ISS с `INSTRID = EQIN` (на 16.11 — 261; совпадает с отбором по
     `SECTYPE` 1, 2, D, см. сверку). Справочник — таблица `instruments` (уточнение E2): бумага вселенной получает строку
     с типом `share`, коротким именем ISS, уровнем листинга и признаком «во вселенной скринера»;
   - бумага ушла с TQBR — признак снимается, строка остаётся: на тикер ссылаются сессии, бэктесты, лоты и шаг цены;
   - T-Invest `Shares` — один запрос «счётом для рыночных данных» (A8). По записи класса TQBR: статус «торгуется» /
     «перерыв» (статус торгов), флаги «для квалифицированных» и «шорт доступен», идентификатор для живых цен (uid или
     FIGI). Записи TQBR нет — «нет на TQBR у брокера» (PIKK, SPBE, ELMT и почти неторгуемые). Тикеры брокера, которых
     нет в списке ISS (HHRU), во вселенную не попадают;
   - сектор — T-Invest по тикеру из записи любого класса (SPBE, ELMT — запись SPBRU); поправка важнее брокера (п. 6);
     русские названия — по развилке 8;
   - состав IMOEX с весами — ISS `statistics/engines/stock/markets/index/analytics/IMOEX` (44 бумаги, один запрос);
   - **лот и шаг цены справочник не пишет** — их ведёт `MarketDataService.ensure_lot_size` с правилами авторитетности
     (S8R-AUDIT-003, A-03); FIGI в строку — только если поле пусто или совпадает, расхождение — в журнал;
   - без «счёта для рыночных данных» ISS-часть идёт, колонки T-Invest пустые с пометкой «не выбран счёт для рыночных
     данных», журнал `market_data_account_missing` (как у дивидендов A-02);
   - когда: раз в сутки ночью и сразу после старта процесса, если последняя синхронизация старше суток (jobstore
     APScheduler в памяти: запуск, пришедшийся на простой, не догоняется). Не в окне `history_backfill` (04:00 МСК):
     ISS — одна страница за раз на процесс.
2. **История дня по ISS и ночной пересчёт** (A9, E1) — по развилке 2:
   - оборот бумаги — медиана `VALUE` ISS `history` за 60 будних сессий; порог ликвидности — по развилке 5, по умолчанию
     10 млн ₽;
   - шкала цвета карты за день — 90-й перцентиль |Δ| за день по вселенной за 250 торговых дней, пересчёт ночью;
   - пока история не набрана (первое заполнение после выкатки), скринер и карта говорят об этом прямо («ликвидность
     считается», шкала — ±3 % из плана), а не показывают пустой список;
   - свечи в `ohlcv_cache` блок не пишет: ночная загрузка D по всему рынку — часть 2 E1 (Б-09), и по A9 это биржевые
     свечи T-Invest, а не ISS.
3. **Снимок рынка** (E1 слой 1, E3) — маршрут модуля `app/screener/`:
   - строка бумаги: цена, изменение за день, оборот сегодня, медианный оборот, капитализация, сектор, уровень листинга,
     вес в IMOEX, статус у брокера и флаги, признак «ликвидная»;
   - **с брокером:** `GetLastPrices` одним запросом по бумагам «торгуется», ключом **самого пользователя**
     (`select_market_data_account(db, user_id)` → `decrypt_market_data_token`, ключ только в памяти), кэш 5 с на
     пользователя; пометка «live»;
   - **без брокера:** снимок ISS раз в 15 с (общий кэш на процесс) с пометкой «задержка 15 мин» и временем данных
     (`UPDATETIME` ISS). PIKK, SPBE и прочие «нет на TQBR» — по ISS с той же пометкой и при брокере;
   - изменение за день — от `PREVPRICE` ISS (у ISS — `LASTTOPREVPRICE`); оборот и капитализация — из ISS при любом
     источнике цены;
   - брокер не ответил — строка по ISS с пометкой, ответ скринера не падает;
   - «счёта для рыночных данных» нет — по развилке 6.
4. **Страница «Скринер»** (E1, E2) — вид по развилке 1:
   - таблица всех бумаг вселенной; по умолчанию — ликвидные, переключатель «все»; фильтры — сектор, уровень листинга,
     статус у брокера, вхождение в IMOEX; сортировка по колонкам;
   - колонка «у брокера»: «торгуется» / «нет на TQBR» / «для квалифицированных» / «шорт доступен» (и «перерыв»);
   - «в избранное» — существующее избранное (`userFavoritesStore.add('instrument', тикер)`); клик по строке —
     график `/chart/<тикер>`;
   - в шапке — источник цен («live» или «задержка 15 мин» и время данных) с подсказкой;
   - автообновление, пока страница на экране: 5 с с брокером, 15 с без; вкладка скрыта — опрос стоит.
5. **Страница «Карта рынка»** (E1) — вид по развилке 1:
   - `<canvas>`, раскладка — `d3-hierarchy` (treemap; новая зависимость, см. «Правила работы»);
   - режим «рынок»: размер — капитализация, по умолчанию только ликвидные, группы по секторам, **клик по сектору — все
     его бумаги** (с неликвидными); режим «IMOEX»: размер — вес в индексе;
   - цвет — изменение за день; насыщенность — по шкале п. 2; плитки меньше 10×10 px — по развилке 3;
   - подпись — тикер и изменение, где помещается; подсказка при наведении — имя, цена, изменение, оборот, сектор;
     клик по плитке — график;
   - автообновление, пока карта на экране (как у скринера); пометка «live» / «задержка 15 мин» с временем данных.
6. **Поправки секторов** (E4):
   - таблица «тикер → сектор» (миграция), поправка важнее брокера, общая для всех, правит владелец (администратор,
     `require_admin`), каждое изменение — в аудит;
   - стартовые поправки — по развилке 8; где их правят — по развилке 4;
   - поправка действует сразу: снимок и карта берут её без ожидания ночной синхронизации.
