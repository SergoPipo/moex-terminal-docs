# Блок Б-07 «ИИ-разметка и алерт новостей» — бриф для Autopilot

Проект — торговый терминал MOEX Trading Terminal. Код — этот репозиторий (`moex-terminal`, worktree

(общая модель алертов, ADR 0023), A-05 «Дефекты этапа 1», Б-02 «Графики: панели и виды» и Б-01 «Новости: сборщик,

(`moex-terminal-docs`). План развития — сводный план 008:
`/Users/sergopipo/Documents/Claude_Code/Moex-Terminal/Спринты/Планы на развитие/008_unified_plan/008_unified_plan.md`.
Порядок блоков — `delivery_blocks.md` в той же папке. Эталон разметки — `d8_news_labels.json` в той же папке.

Других прогонов Autopilot сейчас нет. Сданы и ждут тестового стенда и мержа (свои worktree, в `develop` их нет):
A-02 «Старая история и дивиденды», A-04 «Стоп всему» и Circuit Breaker, Б-04 «Рисунки», починка времени бэктеста
(`fix/backtest-naive-timestamps`). Их файлы — в «Границах блока», «Не трогать».

Почему блок важен:
- Словарь Б-01 привязывает новость к бумаге по словам. Он ошибается на общих словах («система», «вклады», «Мосбиржа»
  как индекс) и не видит косвенных связей («Титов: спрос на игристое» → ABRD). Тип у всех новостей «прочее», тональности
  и важности нет. План 008 (D8): размечает ИИ, словарь — запасной путь.
- Алерт «новость по бумаге» (D7) — единственный способ узнать о новости по своей бумаге, не держа ленту открытой.
- Метки новостей на графике (D7) показывают, где новость легла на цену и отыграна ли она.
- Архив копится с выкатки Б-01. Чем раньше включена разметка, тем больше размеченной истории будет к `ctx.news`.

## Что сделать

Реализовать пункт D8 и оставшиеся от Б-01 части D7 — алерт «новость по бумаге» и метки на графике. Тексты пунктов
приведены ниже дословно — они и есть требования. Порядок: разметка → проверка на эталоне → лента → алерт → метки.

1. **D8 — ИИ-разметка** (шаг после сборщика, `app/news/`):
   - заголовки новых новостей уходят в модель пачками до 20 вместе со списком акций TQBR (261 бумага — тот же список,
     что у словаря); ответ — по схеме JSON;
   - что размечает модель: бумаги **только из переданного списка** (тикер вне списка отбрасывается и считается в журнале),
     охват — компания / отрасль / весь рынок (новость не про рынок — без охвата и без бумаг), тип — список D8 (отчёт,
     дивиденды, сделка, санкции, регулятор, менеджмент, биржа, прочее), тональность для компании — + / − / 0 /
     «неоднозначно», важность 1–3;
   - запись — `news_labels` с `labeler = "ai"`, модель и версия подсказки, бумаги — `news_tickers` этой разметки (схема Б-01,
     ADR 0102);
   - ответ проверяется: JSON по схеме, тикеры из списка, значения из словарей кодов `constants.py`. Неверный ответ — повтор,
     затем разметка остаётся словарной с пометкой;
   - ИИ недоступен, нет провайдера или исчерпан дневной лимит — новость размечена словарём с пометкой, лента и алерты
     работают;
   - в модель уходят только публичные заголовки и список TQBR; данных счёта, позиций, пользователя — нет;
   - задержка разметки замеряется (план: «секунды») и попадает в отчёт.
2. **Провайдер для фоновых задач** (`app/ai/`):
   - вызов провайдера вне чата — функция для фоновых задач с таймаутом и учётом токенов. Сейчас вызова вне чата, ответа
     по схеме JSON и таймаутов нет (см. сверку);
   - настройка «провайдер для фоновых задач» — выбирает владелец (как «счёт для рыночных данных», A8), по умолчанию —
     активный провайдер владельца (развилка 5);
   - дневной лимит токенов фоновых задач (развилка 6); учёт по дням; цены моделей — в настройках провайдера (колонки
     `price_per_1m_prompt` / `price_per_1m_completion` уже есть, сейчас 0);
   - расход за день — токены и стоимость — виден в настройках ИИ.
3. **Проверка модели на эталоне 108 заголовков** — до включения разметки (развилки 1, 3, 4):
   - эталон `d8_news_labels.json` переносится в репозиторий кода как данные проверки;
   - результат: метрика по бумагам, тикеры вне списка, три контрольных заголовка («система», «вклады» не привязываются;
     «Титов: игристое» → ABRD); по типу и тональности — таблица совпадений без порога (в эталоне тип — свободные слова,
     важности нет, см. сверку);
   - модель не прошла — другая модель или словарь (план).
4. **Лента «Новости»** (`NewsPage`):
   - действующая разметка новости — по развилке 2; фильтры «Бумага» и «Тип» — по действующей разметке;
   - новый фильтр «Тональность»;
   - значок «ИИ / словарь» с моделью и версией подсказки уже есть (`labelerText`) — показывать для действующей разметки;
     пометка «словарь: ИИ недоступен / лимит» — когда ИИ не сработал;
   - тональность — подпись «оценка ИИ» рядом с реакцией «до / после», не сигнал; важность — видна.
5. **Алерт «новость по бумаге»** — вид `news` в общей модели `Alert` (правило A3, ADR 0023):
   - условие: список бумаг или весь рынок (развилка 11); фильтр слов; фильтры типа и тональности;
   - фильтр слов — «любое из слов», без учёта регистра, «ё» = «е», поиск подстроки в заголовке («дивиденд» находит
     «дивидендов»);
   - срабатывание: каждая подходящая новость — одно уведомление на алерт; алерт остаётся активным до паузы или
     удаления; история срабатываний — новость, время, кто разметил;
   - момент решения: разметка ИИ готова или прошло ~10 с после получения новости — тогда по словарю с пометкой
     (план D8). Алерты с фильтром типа или тональности — по развилке 12;
   - подписок на поток не держит; входит в лимит активных алертов (развилка 10);
   - каналы — как у алертов: в приложении и Telegram (почты у алертов нет, `EMAIL_ALLOWED_EVENTS`); тип уведомления —
     развилка 9;
   - где создать, увидеть список, поставить на паузу и удалить — развилка 8.
6. **Метки новостей на графике** (D7) — развилка 13:
   - метка — на баре, в который попадает время публикации; вне баров (ночь, выходные) — первый бар после (правило E8);
   - бумаги — по действующей разметке;
   - подсказка при наведении: время, источник, заголовок, тип, тональность «оценка ИИ», реакция «до / после»;
   - запрос новостей бумаги за интервал времени — нового маршрута (сейчас в API ленты только курсор, `from` / `to` нет).

**1. Как считать «верная бумага ≥ 95 %».**
- Факты:
  - у эталона 108 заголовков; бумаги есть у 36 (37 пар), у 72 — нет;
  - «73 % у словаря» в плане — точность: из 48 заголовков, где словарь исследования нашёл бумаги, верен набор в 35;
  - если сравнивать набор бумаг по всем 108 заголовкам, тот же словарь даёт 87 % (94 из 108): пустые наборы совпадают
    сами;
  - словарь Б-01 настроен на этом же эталоне: 36 пар найдено, все верные, из 37. Отличить ИИ от словаря эталон теперь
    почти не может — он проверяет, что модель не хуже порога.
- Варианты:
  - (а) две метрики: точность — из заголовков, где модель назвала бумаги, набор верен целиком, ≥ 95 %; полнота — из 36
    заголовков с бумагами верный набор найден ≥ 95 % (≥ 35 из 36); плюс 0 тикеров вне списка и три контрольных
    заголовка;
  - (б) одна метрика — набор бумаг совпал по всем 108 заголовкам ≥ 95 % (≥ 103 из 108), плюс те же условия.
- Рекомендация — (а): точность сравнима с «73 % у словаря» из плана, полнота не даёт пройти, ничего не находя.

**2. Чья разметка действует, когда есть обе.**

### Фрагмент: D8 (строки 2548–2598)

#### D8. ИИ-разметка новостей

*Этап:* параллельная дорожка, вместе с D7 · *Статус:* ✅ делаем вместе с D7 (принято 2026-10-22; в пакете было «не сейчас»)

**Факты.**
- Эталон — 108 заголовков RSS 19–21.10 с ручной разметкой (`d8_news_labels.json` (приложение 6.1)). Словарь: нашёл бумагу в
  48, **верно в 35 (73%)**; 13 ложных — общие слова («система» ×7, «вклады» → VKCO, «Вкусвилл», «Мосбиржа» как
  площадка или индекс ×4, ISIN облигации). Из 36 заголовков о компаниях нашёл 35; пропуск — косвенная связь («Титов:
  спрос на игристое» → ABRD). Новости о рынке целиком (17) и об отрасли (4) словарь не видит; 51 — не про рынок.
- Тональность против реакции цены (25 пар): **до** публикации цена шла в сторону новости в 7 из 10 однозначных
  случаев; заметных движений **после** — 4: совпало 1 (GAZP +0,73%), наоборот 1 (SPBE −1,14% при «+»), неоднозначно 2
  (OZON «плата для ПВЗ» −1,15%, ALRS «дивполитика» −0,86%). Тональность — подпись к новости, а не сигнал.
- Стоимость (OpenRouter, 21.10.2026): Qwen3.8 Flash $0,15 / $0,47 за 1 млн входных / выходных токенов, DeepSeek V4 Pro —
  от $0,43 / $0,86. 500 новостей в день пачками по 20 ≈ 100 тыс. входных + 20 тыс. выходных токенов в день → **≈ $0,7
  в месяц** (Qwen Flash) или ≈ $1,8 (DeepSeek Pro); с запасом ×3 на кириллицу — меньше $6.

**Решение.**
- **Что размечает ИИ:** бумаги — **только из переданного списка TQBR** (ответ по схеме JSON, тикер вне списка
  отбрасывается); охват — компания / отрасль / весь рынок; тип — отчёт, дивиденды, сделка, санкции, регулятор,
  менеджмент, биржа, прочее; тональность для компании — + / − / 0 / «неоднозначно»; важность 1–3.
- **Словарь остаётся:** мгновенная привязка и запасной путь, если ИИ недоступен или исчерпан лимит. Храним обе разметки;
  в ленте видно, кто разметил (словарь или ИИ, модель и версия подсказки).
- **Тональность — «оценка ИИ», не сигнал:** показывается рядом с реакцией «до / после» (D7); в `ctx.news` — только после
  проверки на архиве (контрольная точка D7, 1–3 месяца).
- **Ключ и модель:** настройка «провайдер для фоновых задач» (по умолчанию — активный провайдер владельца, сейчас Qwen3.8
  Flash), дневной лимит токенов; цены моделей вносятся в настройки — расход виден в Moex. В модель уходят только
  публичные заголовки, данные счёта и позиций — нет.
- **Проверка модели перед включением** — на эталоне 108 заголовков: верная бумага ≥ 95% (у словаря 73%), ни одного
  тикера вне списка. Эталон размечен моделью уровня Claude; дешёвая модель может ошибаться чаще — тогда другая модель
  или словарь.
- **Задержка:** разметка — секунды (замерить при реализации); алерт «новость по бумаге» (D7) ждёт её не дольше ~10 с,
  иначе идёт по словарю с пометкой. Фильтры алерта — по типу и тональности.
- **Когда** — в общем списке доработок вместе с D7 (порядок — B1).

**Где в коде Moex.**
- `app/news/` (D7) — шаг разметки после сборщика: пачки по 20, подсказка со списком TQBR, проверка ответа (JSON,
  тикеры из списка), поля разметки, модель и версия подсказки; повтор при сбое, затем словарь.
- `app/ai/` — вызов провайдера вне чата, настройка «провайдер для фоновых задач», учёт токенов в `ai_usage_daily`,
  лимиты.
- Фронтенд — фильтры по типу и тональности в ленте и алерте, значок «ИИ / словарь», выбор провайдера в настройках ИИ.

**Как проверяем.**
- Эталон: бумаги верны ≥ 95%; «система» и «вклады» не привязываются; «Титов: игристое» → ABRD; тикеров вне TQBR нет.
- ИИ недоступен или лимит исчерпан → разметка словарём с пометкой, лента и алерты работают.
- Расход токенов за день виден в настройках ИИ.
- Алерт «ALRS, тип = дивиденды» срабатывает по разметке ИИ.

**Уточнения 2026-10-23 (проверка однозначности).**
- Провайдер для фоновых задач выбирает владелец (как «счёт для рыночных данных», A8).

**Зависит от:** D7, модуль `app/ai`. **Влияет на:** алерты по новостям (D7), `ctx.news` (позже), скринер (E-блок).
